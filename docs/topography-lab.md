# Topography 俯视等高线

入口：`/ta/topography/`（实验页，带完整参数面板）。`/ta/` 的整页背景使用同一个渲染器，
以 `interactive: false` 运行，只保留暂停与全屏，并由页面暗幕整体压暗约四成：它只是作品层下面的陪衬，
不和标题、项目争夺视线。实验页保持参考视频的原始亮度。原水下首屏已让位，代码保留未使用。

## 参考与边界

视觉参考为用户选定的 MUSYNX RETURN `Dark_2D` 俯视背景。经本地只读核查，参考画面存在于游戏打包视频中；
这里只按逐帧观察到的构图、运动与交战逻辑独立重建，不能声称复刻了游戏运行时 Shader 或原作者公式。

此实现由 AI 辅助编写，使用自己定义的地形函数、路径、单位图形和标注文字。没有复制游戏视频、截图、贴图、模型或着色器代码到网站。
原始游戏资源及本地分析帧不在仓库中；网站后备图与分享图来自本实验的实际渲染。

从参考中确认并保留的约束：

- 正交俯视，无镜头倾斜。镜头只做正北匀速推进 0.4 格/秒（参考视频实测 37.3 px/s），不跟随交战横移；
  120 秒走完 48×48 格的环面周期，首尾无缝，不是静态构图。
- 比例与参考一致：1080p 下网格 92 像素一格，一屏约 20.9 × 11.7 格。其它分辨率与比例按屏幕面积等比缩放，显示同样面积的地图。
- 单位速度取自参考视频逐帧追踪：青色飞翼约 1.0 格/秒，品红攻击机约 1.5，盘旋炮艇约 0.9，编队与登陆艇 0.6–1.1；
  只有导弹、炸弹、鱼雷更快。
- 交战集中在画面左右两侧，中央多为开阔海面，给上层内容留出位置。
- 视角保持 Dark_2D 的正俯视（用户选定），不用录屏里 3D 版的倾斜透视；3D 版的单位细节改用俯视下能读出的方式表达，见下文。

## 入场动画

参考用户的游戏录屏：进入画面时，一道斜向擦除先铺满与网格对齐的方形面板，面板在黑、深灰、浅灰、白之间闪动，
随后逐块镂空成粗边框、边框变细消失，露出底下已经在运行的地图。本实现为 `src/shaders/topography-intro.frag.glsl`，
面板 2 × 2 格、跟随地图坐标，全程约 1.95 秒（真实时间，不受速度参数影响），结束后通道关闭、不再占用 GPU。
减少动态偏好下直接跳过；启用脚本时静态后备图不显示，由入场动画从黑屏揭开，渲染失败或无脚本时才显示后备图。

## 单位与标记

参考视频 Dark_2D 实际是一台正对地面的透视相机：离地的物体从画面中心向外偏移，偏移量约为到中心距离乘以一个系数，
越靠画面边缘越明显，并随镜头推进产生视差。本实现照此处理（`Frame.lift`，静态航迹在线条顶点着色器里做同样的变换）：

- 飞机画在抬升后的位置，地面投影点画准星，两者之间一段细虚线。战斗机的准星是圆环加实心内核，大型飞翼与鱼雷机是方框加实心内块。
  抬升系数取自参考视频的实测：大型飞翼 0.13、战斗机 0.1，盘旋炮艇为飞翼的一半，且它的盘旋圈也一并抬升。
- 从飞机射向地面的导弹、炸弹沿线从抬升位置过渡到地面；鱼雷、舰船航迹在地面上。
- 大型攻击机为后掠飞翼：机头短，两翼细长后掠约 30°、翼展约 1 格，尾部深凹；左翼受光、右翼背光，机身用略低的亮度保持本色。
- 战斗机为对称箭头（长约 0.23 格），凹口接在 2.4 CSS 像素宽的尾迹线头上，整体读作矢量箭头。
- 地面单位为立方体：顶面按 0.012 的系数向外偏，露出朝画面中心一侧的侧面。
- 舰船为叶形船体；空袭命中前目标上有由大收小的锁定环，远程打击与鱼雷艇的目标舰有四角方括号，轰炸标定区里的目标依次被方括号锁住。

## 交战时间轴

时间为循环秒数，`src/lib/topography-battle.ts` 的 `timeline()` 定义全部编排。镜头纬度为 `0.4 × t`，
事件按出现时镜头所在位置摆放，所以随地图漂入画面，而不是固定在屏幕上。
每个事件锚定一个关键时刻（到达目标、领头艇靠岸、编队交汇），进场时间由航程与速度倒推，
所以调整速度不会让交战错过镜头；表中时间为关键时刻附近。

| 时间 | 事件 | 过程 |
| --- | --- | --- |
| 11.6 | 空袭 A | 青色三架飞翼进场，七个射程圈罩住品红地面单位；导弹逐个命中后编队沿原航向飞出画面。 |
| 15 | 登陆 A | 青色四艘登陆艇沿开阔水道驶向滩头，在第一次由海入陆处停下；步兵下船向内陆推进，与哨所互射，双方都有伤亡。 |
| 20 | 轰炸 | 目标区出现标定框；品红四机编队沿弧线进入，在目标前方分批投弹，炸弹斜落到标定区，随后飞出画面。 |
| 32 | 盘旋火力 | 青色炮艇沿半径 3 格的大射程圈盘旋 190°，每 1.2 秒锁定最近的品红守军开火，然后沿切线离开。 |
| 53 | 空袭 B | 反向空袭：品红两机打击青色地面单位。 |
| 58.5 | 鱼雷艇 | 品红鱼雷艇齐射，鱼雷按预判弹着追向青色舰队；约三分之一故意从舰侧掠过，命中的舰船沉没，幸存者加速驶离。 |
| 77.6 | 鱼雷机 | 品红五架攻击机横穿海面，锁定线连到各自目标舰，近距离投放鱼雷后继续飞出画面。 |
| 85 | 远程打击 | 青色舰队的每艘船都被虚线框锁定；品红编队沿长弧线逼近，在 4.4 格射程边缘发射导弹，不停留。 |
| 103.6 | 登陆 B | 品红五艘登陆艇冲滩，青色三架拦截机横穿画面击沉其中一艘；上岸步兵攻向前哨，108 秒三个炮击射程圈落下，四处守军相继被毁。 |

所有弹体（导弹、炸弹、鱼雷）都做迭代预判：弹体飞行期间目标仍在移动，命中点取目标在命中时刻的位置。
登陆艇航线用 `Path.until()` 截到航程 65% 之后的第一次由海入陆处，途中擦过的小岛不算靠岸。

地形上的手工特征（`TERRAIN_FEATURES`、`SEA_BAND`）保证每个事件的陆地或海面位置；
`terrainHeight()` 是着色器高度函数的 CPU 镜像，用于放置单位与判断海岸。两边必须同步修改。

## 文件职责

- `src/pages/ta/topography.astro`：独立页面、无障碍控件与生命周期接入。
- `src/pages/ta.astro`、`src/components/ta/TopographyBackdrop.astro`：把同一渲染器作为 `/ta/` 的整页固定背景，并提供暂停与全屏。
- `src/styles/topography.css`、`src/styles/ta.css`：实验页的全屏画布；TA 页的背景层、内容暗幕与 HUD。
- `src/lib/topography-settings.ts`：参数边界、原生分辨率缓冲尺寸、与参考同比例的取景、环面尺寸与漂移常量。
- `src/lib/topography-terrain.ts`：事件锚点 `SITES`、地形特征、CPU 高度函数与环面取最近距离。
- `src/lib/topography-scene.ts`：Three.js 场景、高度场烘焙、镜头推进、后期和资源释放。
- `src/lib/topography-battle.ts`：单位图形、标注图集、逐帧即时绘制缓冲、九个交战事件与陆地地名标记。
- `src/shaders/topography-height.frag.glsl`：可平铺高度场。地形形状与陆海比例在这里调整，不用辉光掩盖构图问题。
- `src/shaders/topography-map.frag.glsl`：海岸线、分级等高线、网格交点与解析抗锯齿。
- `src/shaders/topography-line.*.glsl`：静态航迹线带；逐顶点出现时间、随单位推进的线头与尾迹亮度、虚线。
- `src/shaders/topography-marker.*.glsl`：射程圈、锁定框、角标、十字、虚线段等 SDF 标记。
- `src/shaders/topography-fill.*.glsl`：机体、舰船、地面单位等实心图形。
- `src/shaders/topography-label.*.glsl`：标注文字图集采样。
- `src/shaders/topography-finish.frag.glsl`：边缘色散与暗角。
- `src/shaders/topography-intro.frag.glsl`：入场面板动画。

## 渲染与交互

高度场为 3072×3072 的单通道半浮点纹理（约 18 MB），噪声按格点周期取模，整幅地形在两个方向上无缝相接，
因此镜头可以无限漂移而不会露出纹理边缘。地形只在初始化与上下文恢复时烘焙，每帧地图着色器只采样高度与梯度。

整个画面是循环时间 `t`（0–120 秒）的纯函数：同一时刻总是同一帧，暂停、固定帧导出与循环接缝都依赖这一点。
航迹线在初始化时一次生成，按每顶点时间属性显隐；单位、射程圈、标注等每帧在 CPU 写入三个动态缓冲后一次上传。

流程：线性 HDR 场景（加法混合）→ UnrealBloomPass（阈值 0.62，只保留最近两级模糊的窄光晕）→ 入场面板（仅开场约 2 秒）→ 色散与暗角 → OutputPass。
单位与线头的颜色高于泛光阈值，射程圈、弹道细线低于阈值，因此只有机体、爆点和线头会晕开。

缓冲按设备像素原生渲染（CSS 尺寸 × devicePixelRatio），不设画质档位，只在超过 GPU 单张缓冲上限时等比缩小；
不做 FXAA 之类的后期抗锯齿，线条只在着色器里做 1 个缓冲像素的解析边缘，因此高分屏上不会被拉伸发糊。
线宽按「缓冲像素 / CSS 像素」换算，不同设备像素比下线宽一致。帧率不设上限，跟随显示器刷新；时间按真实间隔推进，速度与刷新率无关。

支持暂停、原生全屏、等高线/轨迹分层、四个参数滑块、重置、拖动平移。地图在环面上无限重复，平移没有边界。

隐藏页面停止调度；减少动态偏好默认暂停；WebGL 上下文丢失时显示本实验后备图。上下文恢复重新生成高度场。非 BFCache 离页时释放渲染目标、后期、几何、材质、纹理和监听器。

## 本地验证（2026-09-29，去掉镜头跟随、按参考调速后）

测试环境为 Claude 桌面应用内置浏览器（Chromium / WebGL2，devicePixelRatio 1.25），GPU 为 AMD Radeon 880M 集显（ANGLE / Direct3D11）。

- `pnpm test:lab`：11 项通过。`pnpm check`：无错误，保留两个既有提示。`pnpm build`：通过，仍有 Three.js 分包大于 500 KB 的提示。
- 参考视频重新按 4 帧/秒抽取整段：网格周期 92 像素，镜头北移 37.3 px/s，横向 0。
- 用同一套色块追踪脚本分别跑参考视频与本实验整段 120 秒：运动单位速度中位数参考 0.98、本实验 0.96 格/秒；
  品红大型攻击机两边都是 1.50。偏快的样本只来自飞行中的弹体，参考视频同样如此。
- CSS 1920×1080、设备像素比 1.25 时缓冲为 2400×1350，连续渲染每帧约 2.4 ms（含 CPU 编排与后期）。只是这台机器的数字。
- 循环接缝：120.05 秒与 0.05 秒两帧逐像素最大差异为 0（上一轮验证，镜头推进方式未变）。
- 桌面九帧与手机 375×812（缓冲 750×1624）十帧检查：镜头不横移，交战在左右两侧；手机是同面积地图的竖向切片，靠边的交战可能只露出一部分。
- 首次渲染时 three.js 曾对二维顶点缓冲报包围球 NaN，已给动态缓冲固定包围球，控制台不再出现。

阶段一曾在另一台机器上验证全屏、上下文丢失与恢复、减少动态偏好和多视口无横向溢出；
这些外壳代码本次未改动，但交战层重做后没有逐项重跑。

## 固定帧与后备图

仅开发模式挂接 `window.__topographyCapture(seconds?, introSeconds?)` 与 `window.__topographyBench(frames?)`：
前者固定动画时间并导出实际 PNG（传入秒数会暂停动画；第二个参数叠加入场动画的某一刻），后者用于测每帧耗时。都不是生产页面交互，也无需常驻开启 `preserveDrawingBuffer`。
导出前会按当前布局重新取尺寸，即使页面在后台也不会导出旧尺寸的画布。

- 桌面后备图：`public/assets/ta/topography-poster.webp`，1600×900，由 CSS 1920×1080 下第 8 秒（默认起始时刻）的原生缓冲缩小而来，也是 `/ta/` 整页背景的加载前画面。
- 手机后备图：`public/assets/ta/topography-mobile.webp`，750×1624，同一时刻的竖屏取景。
- 社交分享图：`public/assets/ta/topography-og.webp`，1200×630，取自第 38 秒的盘旋火力，`/ta/` 的 `og:image` 指向它。

调整着色器或编排后应重新从实验页画布导出这三张图，不要用带页面文字的截图或游戏素材。
